Research engineering · 2026

Reverse-engineering how three AI search engines pick their citations

I built the data-collection instrument for an information-systems study on AI search. It answered the question it was built for — and then told us the study's central comparison didn't mean what we thought it meant.

  • Role Sole developer
  • Context Faculty-supervised IS research
  • Duration ~5 weeks
  • Stack Python · CDP · Selenium

The problem

When Perplexity, ChatGPT, or Gemini answer a question, they retrieve a set of candidate web pages and then cite a few of them. Our study asked what makes one page get cited over another — which means the interesting data isn't the citations. It's the pages that were retrieved and then passed over.

Every platform's public API hides exactly that. The APIs return the cited sources only, and their search backends aren't even the ones the real products use. The uncited candidates exist only in the web UI's own network traffic.

So the instrument had to be a browser: drive each product's live interface, intercept the response stream, and reconstruct both the retrieved pool and the cited subset from formats none of the three vendors document.

  • 3 Platforms parsed
  • ~300 Usable runs
  • 0 Documented formats
  • 9 Wrong conclusions caught

What I built

A two-phase capture → extract pipeline with a per-platform adapter for each engine. Capture drives the live UI and records the raw response stream, the rendered HTML, and a screenshot into a per-run bundle. Extract parses those bundles offline, so every number in the study can be re-derived without re-querying a platform — and so a parser bug is a re-run of the parser, not a re-run of the collection.

Two design rules did most of the work. Fail loudly: a blocked or empty run is recorded as a failure with a reason, never as a silent zero — a scraper that quietly returns nothing is worse than one that crashes, because the empty result flows into the analysis looking like data. Keep the raw bytes: every claim traces back to a saved artifact.

Three problems worth describing

  • 01 · The capture race that wasn't

    Rich answers never finish

    Captures were missing roughly half the time. The working theory was a buffer eviction race. It wasn't: the code read each response body after the stream reported completion, and answers containing images or widgets keep the connection open indefinitely — the completion event never fires. Any capture gated on it hangs or misses. The fix was to stream bytes as they arrive and settle on idle rather than on completion. A 526 KB response that never closed its stream then captured cleanly.

  • 02 · An undocumented nested format

    Finding the citation link in Gemini

    Gemini returns Google's nested-array encoding: an XSSI guard, length-prefixed frames, and an inner payload that is a double-escaped JSON string. Nothing is named — a source is a bare array, and whether it was cited is encoded positionally. I dumped raw subtrees across grounded and ungrounded runs until the rule fell out: a source is cited when its fourth slot holds a sentence carrying character-span offsets into the answer. The official API docs describe a redirect-wrapper structure for this; the web product has zero of them. Reading the docs would have produced a parser that found nothing.

  • 03 · The vendor changed the format mid-study

    A migration disguised as a block

    Partway through a collection sweep, every new capture started failing identically. It looked like rate limiting or bot detection. It was neither — the platform had A/B-rolled a new response schema, and my validator reported the unfamiliar shape as a block. The repair had to be conservative: run the old parse path first and fall back to the new one only when it yields nothing, so that already-analyzed captures stay byte-identical rather than silently changing published numbers. It recovered nine runs and cost zero. The lasting lesson is a monitoring one — "we were blocked" and "the format moved" must not produce the same error.

The finding that changed the study

With all three adapters working, the headline number was supposed to be a simple comparison of how selectively each engine cites. Here is what came out:

Citation behaviour across ~300 runs
Measure Perplexity ChatGPT Gemini
Runs citing at least one source 84% 100% 100%
Retrieved sources actually cited 38% 79% 100%
What its “pool” contains a real retrieval set everything referenced only what it cites
Retrieved-but-uncited pages genuine demoted, not unused none exist

The three engines look almost identical at the level of “did this answer cite anything,” and wildly different one level down. That spread isn't mostly behaviour — it's three incompatible definitions of what counts as retrieved.

Our core research question compares pages within a retrieved pool. Only one of the three platforms exposes such a pool. Gemini publishes only what it cites, so there is nothing to compare against; ChatGPT's “uncited” sources turn out to be demoted to secondary evidence rather than passed over. The cross-platform comparison the study was designed around was measuring a different object on each platform.

That is a negative result about our own instrument, and it was the most valuable thing the pilot produced. It redirected the project toward a controlled design — supplying the candidate documents ourselves, so the pool is identical by construction — and it arrived before months of analysis had been built on the assumption.

How I worked

The project log records nine claims I made and later had to correct — including one I had committed to the repository and reported to my supervisor. Two were his catches, not mine.

They share a cause: I generalized a structure from a single captured example, or trusted a vendor's documentation, instead of reading the actual bytes. Every correction came from dumping the real artifact. That hardened into the rule the rest of the work ran on — inspect the failing artifact before writing a line of code against it — and into a habit of writing down the wrong turns, because on an instrument nobody else has built, the record of what isn't true is most of the documentation.
